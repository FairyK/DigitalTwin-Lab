## 2. Key Concepts

### 2.1 Variable

Variable 用于保存 Actor 当前的状态数据。

在 `BP_Motor` 中使用了：

* `RPM`：电机转速
* `Temperature`：电机温度
* `Running`：电机是否运行
* `Fault`：电机是否发生故障

可以把一个电机理解成：

```text
Motor01
├── RPM
├── Temperature
├── Running
└── Fault
```

这些变量共同描述了电机当前的运行状态。

---

### 2.2 Get / Set

`Get` 用于读取变量当前的值。

例如：

```text
Get RPM
```

表示读取当前 RPM。

`Set` 用于修改变量的值。

例如：

```text
Set RPM
```

表示修改 RPM。

可以理解为：

```text
Get → 读取数据

Set → 修改数据
```

---

### 2.3 Event Tick

`Event Tick` 是 UE 中会持续执行的事件。

在本次实验中使用 Tick 模拟电机状态持续更新。

基本逻辑：

```text
Event Tick
    ↓
读取当前状态
    ↓
计算新的状态
    ↓
Set 修改变量
```

它可以用于理解实时数据不断更新的基本机制。

---

### 2.4 Branch

`Branch` 用于进行条件判断。

本次实验中使用：

```text
Running
   ↓
Branch
 ┌─┴─┐
True False
 ↓     ↓
运行   停止
```

类似于 Python 中的：

```python
if Running:
    ...
else:
    ...
```

## 3. Experiment

本次实验基于之前创建的 `BP_Motor`。

### 3.1 RPM 自动变化

通过：

```text
Event Tick
    ↓
Get RPM
    ↓
计算新的 RPM
    ↓
Set RPM
```

实现 RPM 持续变化。

这让我理解了 Blueprint 中：

```text
事件
 ↓
读取变量
 ↓
计算
 ↓
修改变量
```

这一基本执行流程。

---

### 3.2 Temperature 根据 RPM 变化

建立了 RPM 与 Temperature 之间的简单关系：

```text
RPM 越高
    ↓
Temperature 越高
```

通过 Blueprint 计算新的 Temperature，并使用 `Set Temperature` 更新电机状态。

这模拟了真实设备中：

```text
设备运行状态
    ↓
传感器数据
    ↓
设备状态变化
```

虽然目前只是简单的数学模拟，但已经开始具备数字孪生中的“状态关联”概念。

---

### 3.3 Running 控制电机状态

使用 `Running` 作为电机运行状态：

```text
Running = True
    ↓
电机持续运行
    ↓
RPM 持续变化
    ↓
Temperature 持续变化
```

当：

```text
Running = False
```

则停止状态更新。

通过这个实验进一步理解了：

> Actor 不只是场景中的一个模型，也可以拥有描述自身状态的数据。

---

### 3.4 Fault 状态

增加 `Fault` Boolean 变量，用于表示电机是否处于故障状态。

基本逻辑：

```text
Fault = False
    ↓
正常运行

Fault = True
    ↓
Temperature 更快升高
```

这进一步模拟了设备状态之间的关系。

## 4. Digital Twin Understanding

本次学习开始建立对数字孪生的一个重要认识：

数字孪生并不是简单地：

```text
把真实设备建模到 UE
```

而是：

```text
真实设备
    ↓
设备数据
    ↓
数字孪生对象
    ↓
更新 Actor 状态
    ↓
UE 中实时表现
```

例如未来真实电机产生：

```text
RPM = 1500
Temperature = 63
Running = True
```

那么 UE 中对应的：

```text
Motor01
├── RPM = 1500
├── Temperature = 63
└── Running = True
```

也就是说，UE 中的 Actor 开始成为一个“具有状态的数据对象”。

## 5. Current Architecture

目前学习到的基本结构：

```text
              BP_Motor
                 │
       ┌─────────┼─────────┐
       ↓         ↓         ↓
      RPM   Temperature  Running
       │         │         │
       └─────────┼─────────┘
                 ↓
              Motor01
                 ↓
          UE Digital Twin
```

未来可以进一步扩展为：

```text
真实设备
   ↓
PLC / Sensor
   ↓
MQTT / OPC UA
   ↓
Backend
   ↓
UE
   ↓
Motor01
   ↓
更新 RPM / Temperature / Running
```

或者：

```text
Isaac Sim
   ↓
ROS 2
   ↓
UE
   ↓
Robot01
```

## 6. Important Understanding

本次学习最大的收获不是记住几个 Blueprint 节点，而是理解：

> **数字孪生对象 = 模型 + 状态 + 数据驱动**

之前的 `Motor01` 更像是一个放在 Level 中的模型。

经过本次实验后，开始变成：

```text
Motor01
├── 外观
├── RPM
├── Temperature
├── Running
└── Fault
```

也就是说，虚拟对象开始具备与真实设备对应的状态。

这也是后续接入 MQTT、OPC UA、ROS 2 等实时数据的基础。
