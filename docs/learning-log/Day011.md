# Day011：UE5 数字孪生——故障事件与动态材质

## 1. 今日学习目标

在已有 `BP_Motor`、`ApplyMotorData`、`BP_MotorManager` 和电机状态变量的基础上，进一步建立数字孪生的状态变化响应机制：

- 使用 Event Dispatcher 广播电机故障事件。
- 区分状态更新和状态变化事件。
- 使用动态材质让电机的运行状态在三维场景中可视化。
- 为后续接入 MQTT、真实设备数据和统一告警机制做准备。

## 2. 核心知识

### 2.1 状态与事件的区别

状态描述设备当前是什么情况，事件描述设备发生了什么变化。

例如：

- `Fault = false`：当前没有故障。
- `Fault = true`：当前处于故障状态。
- 从 `false` 变成 `true`：发生了一次故障触发事件。

如果每次收到 `Fault = true` 都广播故障事件，就可能重复告警。因此，后续应使用状态边沿检测，只在 `false → true` 时触发故障事件。

### 2.2 Event Dispatcher 的作用

`OnMotorFault` 是电机蓝图对外广播故障消息的接口。

基本流程：

`BP_Motor` 检测故障 → 广播 `OnMotorFault` → `BP_MotorManager` 接收事件 → 执行统一告警或记录逻辑。

Dispatcher 负责在 Unreal Engine 内部通知已绑定的监听者；它本身不是 MQTT 或网络通信接口。

### 2.3 动态材质（Material Instance Dynamic）

动态材质允许在运行时修改材质参数，而不用为每种状态创建一份独立材质。

计划使用 `MotorColor` 参数表示电机状态：

- 灰色：停止或默认状态。
- 绿色：运行状态。
- 红色：故障状态。

每个电机实例应创建并保存自己的 `MotorMID`，避免修改一个电机时意外影响另一个电机。

### 2.4 状态与显示的关系

建议采用统一更新链路：

`ApplyMotorData` 更新设备状态 → `UpdateMotorVisual` 根据最新状态设置材质 → 场景显示设备状态。

故障颜色优先级最高，其次是运行状态，最后是默认状态。这样即使设备处于运行中，一旦发生故障，仍然能显示红色。

## 4. 与数字孪生整体架构的联系

当前实验仍在 Unreal Engine 内部验证状态处理和可视化。后续完整数据链路为：

真实设备或模拟器 → MQTT / OPC UA → 数据接收与校验 → 设备 ID 映射 → `BP_Motor.ApplyMotorData` → 状态变化事件 → 动态材质与告警显示。

其中，`device_id` 用于找到对应的电机 Actor；`ApplyMotorData` 统一更新设备状态；Event Dispatcher 通知场景内的监听者；动态材质负责展示状态。
