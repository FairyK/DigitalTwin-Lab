## 二、MQTT 整体通信流程

```text
Python Publisher
    ↓
生成电机状态
    ↓
Python 字典 → JSON 字符串
    ↓
MQTT publish()
    ↓
Mosquitto Broker
    ↓
根据 Topic 转发消息
    ↓
Subscriber 接收消息
    ↓
bytes → str → Python 字典
    ↓
数据校验
    ↓
后续设备路由与 UE 更新
```

## 三、Publisher 代码理解

### 1. 模块导入

- `json`：序列化和解析 JSON。
- `time`：控制模拟数据的发送间隔。
- `datetime`：生成时间戳。
- `paho.mqtt.client`：提供 MQTT 客户端能力。

### 2. 电机状态字典

使用嵌套字典维护多台电机的状态，例如：

```python
motors = {
    "Motor01": {
        "rpm": 1200,
        "temperature": 42.0,
        "running": True,
        "fault": False,
        "sequence": 0,
    }
}
```

外层键用于标识设备，内层字典保存设备状态。

这与 UE 中通过 `MotorMap` 查找电机的设计思想相似，但两者属于不同程序中的不同数据结构。

### 3. MQTT 客户端与连接

```python
client = mqtt.Client(
    mqtt.CallbackAPIVersion.VERSION2,
    client_id="day014-publisher",
)
```

创建 MQTT 客户端对象并指定客户端标识。

```python
client.on_connect = on_connect
client.connect("127.0.0.1", 1883, keepalive=60)
```

注册连接回调并发起连接。

`client.on_connect = on_connect` 是注册函数，不是立即调用函数。连接结果被客户端处理后，Paho 才会调用相应回调。

### 4. 消息组织与发布

`make_message()` 将设备 ID、时间戳、序号和设备状态组织成统一的数据结构。

`json.dumps()` 将 Python 字典序列化为 JSON 文本。

`client.publish()` 将消息发布到指定 Topic。

示例 Topic：

```text
digitaltwin/factory/motors/Motor01
digitaltwin/factory/motors/Motor02
```

主要参数：

- `qos=1`：至少一次交付，可能重复。
- `retain=False`：不要求 Broker 保留该消息供未来订阅者立即获取。
- `wait_for_publish()`：等待当前消息的发布流程完成，但不代表 UE 已成功更新。

`while True` 用于持续生成和发布模拟数据，`time.sleep(1)` 用于控制循环间隔。

## 四、Subscriber 代码理解

### 1. Topic 订阅

```python
client.subscribe(
    "digitaltwin/factory/motors/+",
    qos=1,
)
```

`+` 是 MQTT 单层通配符，可匹配不同电机 ID 所在的单个 Topic 层级。

### 2. 消息接收与数据转换

```python
payload_text = msg.payload.decode("utf-8")
data = json.loads(payload_text)
```

转换过程：

1. `msg.payload`：通常为 bytes。
2. `decode("utf-8")`：将字节解码为字符串。
3. `json.loads()`：将 JSON 文本解析为 Python 对象；JSON 对象通常解析为字典。

发送端与接收端的转换方向相反：

```text
发送：dict → JSON str → 消息载荷
接收：消息载荷 → str → dict
```

### 3. 数据校验

Subscriber 需要检查：

- 必需字段是否存在。
- `schema_version` 是否受支持。
- `device_id` 是否属于允许的设备。
- 数值和布尔字段的类型是否正确。
- 转速和温度是否满足当前实验设定的范围。
- Topic 中的设备 ID 是否与 JSON 内的 `device_id` 一致。

合法 JSON 不代表业务数据一定正确。

`raise ValueError()` 可以主动终止当前消息的正常处理流程；`try/except` 则用于捕获预期错误，避免一条无效消息直接导致整个程序退出。

注意：实验中的温度范围等限制只是教学示例，实际项目应根据设备规格确定。

## 五、回调函数

回调函数是预先注册、在特定事件发生后由库调用的函数。

```python
client.on_connect = on_connect
client.on_message = on_message
```

二者分别用于处理连接事件和收到消息的事件。

回调注册与网络循环是不同的事情。Subscriber 通常使用 `loop_forever()` 持续处理网络事件；Publisher 可使用 `loop_start()` 在后台处理网络循环，同时在主线程生成并发布数据。

## 六、QoS 1 与消息去重

QoS 1 提供至少一次交付语义，因此业务处理可能遇到重复消息。

可以使用每台设备的 `sequence` 记录已处理序号，拒绝重复或过期的数据。

简化示例：

```python
previous = last_sequence.get(device_id)

if previous is not None and sequence <= previous:
    return

last_sequence[device_id] = sequence
```

这适用于序号单调递增、主要关心最新状态的简化场景。真实系统还需要考虑程序重启、序号重置、乱序消息及历史数据完整性。
