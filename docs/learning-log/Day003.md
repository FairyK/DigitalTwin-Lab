## 二、今天学习的核心概念

### 1. Reference

Reference 可以理解为：

> 指向某一个具体对象的引用。

场景中存在：

```text
Motor_01
Motor_02
```

它们虽然都来自：

```text
BP_Motor
```

但属于两个不同的 Actor Instance。

因此如果要操作 `Motor_02`，不能只说：

```text
Set Temperature = 100
```

而需要先明确：

```text
哪个 Motor？
        ↓
Motor_02 Reference
        ↓
Temperature
```

---

### 2. Object Reference

创建变量：

```text
TargetMotor
```

类型：

```text
BP_Motor Object Reference
```

该变量可以保存某个具体 `BP_Motor` 实例的 Reference。

实际设置为：

```text
Motor_01
└── TargetMotor → Motor_02
```

因此 `Motor_01` 可以通过 `TargetMotor` 找到 `Motor_02`。

---

### 3. Self

在 `BP_Motor` 内部：

```text
Motor_01 执行 BP_Motor
→ Self = Motor_01

Motor_02 执行 BP_Motor
→ Self = Motor_02
```

同一个 Blueprint Class 被不同 Instance 执行时，`Self` 指向当前正在执行的那个实例。

---

### 4. BeginPlay

`Event BeginPlay` 表示：

> Actor 开始运行时触发的一次事件。

由于：

```text
Motor_01
Motor_02
```

都是 `BP_Motor` 的实例，所以运行时两个 Actor 都会执行各自的 `BeginPlay`。

---

### 5. 执行线与数据线

Blueprint 中观察到两类重要连接：

```text
白色线
= 执行流程
```

```text
彩色线
= 数据传递
```

例如：

```text
BeginPlay
   │ 白色执行线
   ▼
Is Valid
```

而：

```text
TargetMotor
   │ 彩色 Reference 数据线
   ▼
Object
```

---

### 6. Is Valid

Reference 不一定永远指向有效对象。

例如：

```text
TargetMotor → Motor_02
```

是有效 Reference。

而：

```text
TargetMotor → None
```

是无效 Reference。

因此可以使用：

```text
Is Valid
```

先判断目标对象是否存在。

## 三、完成的实践

### 实验：Motor_01 控制 Motor_02

Level：

```text
Motor_01
Motor_02
```

设置：

```text
Motor_01.TargetMotor = Motor_02
```

Blueprint 逻辑：

```text
Event BeginPlay
      ↓
   Is Valid
      ↓
Set Temperature
      ↑
 TargetMotor
```

最终实现：

```text
Motor_01
   ↓
TargetMotor Reference
   ↓
Motor_02
   ↓
Temperature = 100
```

运行后验证成功。

## 五、出现过的现象

第一次运行时出现：

```text
0.0
66.0
```

原因是两个 `BP_Motor` Instance 都会执行 `BeginPlay`：

```text
Motor_01
TargetMotor → Motor_02
→ Get Temperature
→ 66.0
```

而：

```text
Motor_02
TargetMotor = None
→ 没有有效目标
→ 得到异常/默认结果
```

由此进一步理解了：

```text
Reference
→ 是否有效
→ Is Valid
```
