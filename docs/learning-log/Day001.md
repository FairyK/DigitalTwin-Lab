# 二、程序与进程

程序：

代码文件。

进程：

程序运行后的实例。

理解：

UE、Python Backend、MQTT Broker都是独立运行的进程。

不同进程拥有独立内存，因此不能直接访问对方变量，需要通信。

# 三、网络基础

网络：

让多个计算设备交换信息的一套系统。

访问流程：

域名

↓

DNS解析

↓

IP地址

↓

端口

↓

具体服务

↓

HTTP/WebSocket/MQTT通信

## DNS

作用：

将域名转换为IP地址。

例如：

[www.xxx.com](http://www.xxx.com)

↓

服务器IP

## IP

作用：

找到网络中的设备。

## Port

作用：

找到设备上的具体程序。

# 四、通信协议理解

## HTTP

应用层协议。

特点：

请求-响应模式。

适合：

一次性获取数据。

例如：

UE请求：

获取电机当前温度。

## WebSocket

应用层协议。

特点：

建立持续双向通信连接。

适合：

实时数据更新。

例如：

传感器数据实时同步到UE。

## MQTT

应用层协议。

特点：

发布/订阅模型。

结构：

设备

↓

MQTT Broker

↓

订阅者

作用：

实现设备和系统之间解耦。

# 五、API理解

API：

程序对外提供的调用接口。

作用：

隐藏内部实现，让其他程序按照规则获取功能。

例如：

UE通过API请求：

获取电机温度。

# 六、Python对象模型

## 类 Class

对象创建模板。

## 对象 Object

根据类创建的具体实例。

## 实例 Instance

某个类创建出来的对象。

## **init**

初始化对象数据。

## self

表示当前对象本身。

# 今日思考

1. 为什么UE不能直接读取Python变量？

答案：

因为UE和Python是两个独立进程，拥有独立内存，需要通过通信机制交换数据。

2. 为什么100个机器人应该使用Robot类创建对象？

答案：

因为机器人具有共同属性，可以通过类复用代码，通过创建对象表示不同机器人。
