## 二、今日学习内容

### 1. Event 是执行入口

更准确的理解：

> Event 是一个执行入口；当对应事件发生时，从这个入口开始执行连接在后面的 Blueprint 逻辑。

例如：

```text
BeginPlay
    ↓
Actor 开始运行时触发

1 Pressed
    ↓
玩家按下 1 时触发

2 Pressed
    ↓
玩家按下 2 时触发
```

不同 Event 是不同的执行入口，不会因为位于同一个 Event Graph 就自动按从左到右全部执行。

### 2. Blueprint 执行流

Blueprint 不是“整个 Event Graph 从左到右执行”，而是哪个 Event 被触发，就从哪个 Event 的 Exec 输出开始沿白色执行线运行。

例如：

```text
Event BeginPlay
      ↓
Enable Input
```

表示游戏开始后触发 BeginPlay，然后执行 Enable Input。

而：

```text
2 Pressed
    ↓
StartMotor
```

是另一条独立执行链。

整体可以理解为：

```text
                 BP_Motor
                    │
       ┌────────────┼────────────┐
       ↓            ↓            ↓
   BeginPlay     1 Pressed    2 Pressed
       ↓            ↓            ↓
Enable Input    StopMotor    StartMotor
```

### 3. Exec 执行线与 Data 数据线

**Exec 白线**主要回答：

> 什么时候执行？执行路径往哪里走？

**Data 彩色线**主要回答：

> 执行的时候使用什么数据？

例如：

```text
Event BeginPlay
      │ Exec
      ↓
    Branch
      ↑
      │ Boolean Data
 Get Running
```

白线决定什么时候执行 Branch；`Running` 数据决定 Branch 走 True 还是 False。

### 4. Enable Input

今天确认键盘没有反应的实际原因是第一次测试时没有让游戏视口获得焦点。点击游戏窗口后，键盘事件可以正常响应。

输入链可以理解为：

```text
Keyboard
   ↓
UE Input System
   ↓
Actor 获得输入
   ↓
Keyboard Event
   ↓
Function
```

`Enable Input` 用于让 Actor 能接收玩家输入。

重要区别：

```text
BeginPlay
   ↓
Enable Input
```

是一条初始化执行链，不需要：

```text
Enable Input
   ↓
StartMotor
```

才能让键盘输入生效。

### 5. StartMotor / StopMotor

当前 BP_Motor：

```text
StartMotor()
    ↓
Running = true
    ↓
RPM = 1500
```

```text
StopMotor()
    ↓
Running = false
    ↓
RPM = 0
```

键盘：

```text
1 Pressed → StopMotor
2 Pressed → StartMotor
```

已经能够正常响应。

## 四、Blueprint 当前执行模型

```text
                  Event
                    ↓
              Exec 执行流
                    ↓
                 Function
                    ↓
          ┌─────────┴─────────┐
          ↓                   ↓
       Variable             Branch
          ↓                   ↓
       状态数据             条件决策
          │                   │
          └─────────┬─────────┘
                    ↓
              Actor 新状态
```

同时：

```text
Reference
    ↓
找到具体对象
```

目前已经形成：

```text
Reference
    +
Function
    +
Variable
    +
Branch
    +
Event
```

共同构成 Blueprint 基本对象行为逻辑的认识。

## 五、与传统编程的快速映射

| Blueprint | 传统编程中的近似概念 |
|---|---|
| Variable | 变量 / 对象状态 |
| Get | 读取变量 |
| Set | 修改变量 |
| Function | 函数 / 方法 |
| Branch | if / else |
| Event | 事件回调 / 事件入口 |
| Object Reference | 对象引用 |
| Exec Wire | 控制流 |
| Data Wire | 数据流 |

## 七、今日总结

今天最重要的不是增加了多少节点，而是理解了：

> **Blueprint 是事件驱动的可视化程序。**

核心执行模型：

```text
事件发生
   ↓
Event 作为执行入口
   ↓
沿 Exec 白线执行
   ↓
调用 Function
   ↓
读取 / 修改 Variable
   ↓
Branch 做决策
   ↓
改变 Actor 状态
```

这套模型将作为后续 UE、机器人数字孪生和实时数据驱动逻辑的基础。
