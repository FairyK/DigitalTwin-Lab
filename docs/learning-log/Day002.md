## 三、核心概念

### 1. Project

Project 是整个 UE 工程。

数字孪生项目可以理解为：

```text
DigitalTwin Project
```

其中包含场景、模型、材质、Blueprint、代码等各种资源。

---

### 2. Level

Level 可以理解为一个三维场景。

例如：

```text
Factory_Level
```

里面可以放置：

* 电机
* 机械臂
* 传送带
* 摄像头
* 灯光
* 厂房等

Level 本身不是某一个具体设备，而是组织场景内容的空间。

---

### 3. Actor

Actor 是可以放入 Level 中的实体。

例如：

```text
Motor_01
Motor_02
Robot_01
Camera_01
Conveyor_01
```

这些都可以作为场景中的 Actor。

Actor 可以拥有自己的：

* 位置
* 旋转
* 缩放
* Component
* 状态数据
* 行为逻辑

---

### 4. Component

Component 可以理解为 Actor 所拥有的功能或组成部分。

例如：

```text
Motor_01
│
├── StaticMeshComponent
├── CollisionComponent
├── TemperatureComponent
└── MotorControlComponent
```

核心理解：

> Actor 更像一个场景中的实体，Component 用来给这个实体提供能力或组成部分。

---

### 5. Asset

Asset 是 UE 项目中的资源。

例如：

```text
Cube
SM_Motor
Texture
Material
BP_Motor
```

其中 Cube 是一个 Static Mesh Asset。

需要区分：

```text
Cube
↓
模型资源

StaticMeshComponent
↓
让 Actor 使用这个模型

Actor
↓
场景中的实际实体
```

---

## 四、Blueprint Class 与 Instance

创建了：

```text
BP_Motor
```

它是一个 Blueprint Class，可以理解为“电机 Actor 的模板/类”。

可以由它创建多个实例：

```text
BP_Motor
│
├── Motor_01
├── Motor_02
└── Motor_03
```

这些实例共享 Blueprint 中定义的结构和逻辑，但每个实例拥有自己的状态数据。

核心理解：

> 共享定义，独立状态。

---

## 五、创建的 BP_Motor

本次实际创建：

```text
BP_Motor
│
├── DefaultSceneRoot
└── StaticMesh
       └── Cube
```

并创建了三个变量：

```text
Temperature : Float
RPM         : Float
Running     : Boolean
```

并成功设置为 Instance Editable，使得场景中的不同 BP_Motor 实例可以分别修改这些状态。

## 六、实际实验

完成了：

* 创建 `BP_Motor`
* 添加 Static Mesh Component
* 使用 Cube 作为模型
* 创建 Temperature
* 创建 RPM
* 创建 Running
* 设置 Instance Editable
* 将 BP_Motor 放入 Level

过程中发现：

> Cube 一开始在场景中看不见。

最终发现原因是模型太小，将缩放调整到约 `20` 后可以正常看到。

这说明：

> UE 中 Actor、Component、Mesh Asset 是不同层级的概念，模型本身的尺寸也会影响场景中的实际可见效果。

## 七、数字孪生联系

```text

│
├── StaticMesh
│      ↓

│
├── Temperature
│
├── RPM
│
└── Running

数字孪生系统

   ↓
Temperature / RPM / Running
   ↓

```

未来则可以由外部数据系统驱动。
